# صُنّاع CON — تنفيذ التطبيق الإداري

## هوية التطبيق
- تطبيق Android مستقل للأدمن الرئيسي والمديرين والمشرفين.
- الفرع: `feature/sonaa-con-admin-app`.
- الاسم: صُنّاع CON — package: `com.sonaa.con`.
- اللوجو في شاشة الدخول هو نفس ملف المصدر المستخدم في تطبيق العميل والفني: `assets/LOGO_UPLOAD_HERE/logo.png`.
- الـ launcher icon والـ adaptive icon والـ splash تُولد من ملف اللوجو الرسمي نفسه داخل workflow البناء، تمامًا مثل تطبيق العميل والفني.
- لوحة ألوان مستقلة بدرجات أزرق ملكي أعمق وتركواز، محفوظة في `src/theme/con-colors.js`.

## تسجيل الدخول والحماية
- تسجيل الدخول عبر `POST /api/admin/login` ثم جلب ملف الصلاحيات من `GET /api/admin/me`.
- تخزين token في Expo SecureStore.
- لا يسمح التطبيق بتسجيل العميل أو الفني.
- الخادم هو المرجع النهائي للصلاحيات. إخفاء الأقسام في التطبيق لتحسين التجربة فقط، وكل endpoint محمي من الخادم.
- الأدمن الرئيسي يُعرف من `adminRoleLabel === "أدمن رئيسي"`، وتظهر له كل الأقسام الإدارية وسجل التدقيق وحسابات الإدارة.
- الأدوار الفرعية: مدير، مشرف أول، مشرف، قراءة فقط. تُعرض الأقسام وفق مصفوفة الصلاحيات الافتراضية، مع تطبيق الاستثناءات الفردية sparse overrides.
- أي رفض 403 من الخادم يعرض للمستخدم ولا يتم تجاوزه من التطبيق.

## الأقسام الموصولة حاليًا
لوحة المؤشرات، الطلبات، الفنيون، العملاء، مراجعة الصوت، الشكاوى، طلبات الشحن، المناطق، الخدمات والمهن، المحافظ، التسعير، الإعدادات، المحتوى، خدمة العملاء، العروض، الإشعارات، استعادة الحساب، بيانات العملاء، نشر الطلبات. الأدمن الرئيسي لديه كذلك حسابات الإدارة وسجل التدقيق.

## ملاحظات التكامل
- تم فصل التطبيق عن كود عميل/فني main باستبدال مدخل التطبيق على فرع CON فقط؛ لا يؤثر ذلك على main أو APK العميل والفني.
- ملف Firebase الخاص بالتطبيق القديم لم يُربط بهذه الحزمة الجديدة لتجنب تعارض package name. البناء المحلي لا يعتمد على Firebase. إشعارات FCM الفعلية تحتاج تسجيل Android app جديد باسم `com.sonaa.con` وإضافة ملف google-services.json الخاص به قبل تفعيل push production.
- كل أقسام البيانات تقرأ من API الحالي؛ الأوامر الحساسة لا تُتاح إلا إذا كان الخادم يدعمها ويقبل صلاحية الدور.
